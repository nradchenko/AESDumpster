## Project Overview

AESDumpster is a cross-platform (Windows/Linux) console tool that extracts AES encryption keys from Unreal Engine 4/5 game executables (UE 4.19 – 5.3) by binary signature scanning. On Windows it is a Visual Studio 2022 C++ project (toolset v143, C++ latest standard, Unicode); on Linux it builds with g++ via the root `Makefile`. The tool scans files as raw bytes, so the Linux build analyzes Windows PE binaries exactly like the Windows build does. No CMake, no package manager.

## Build

Solution: `AESDumpster/AESDumpster.sln` (note the nesting). Configurations: Debug/Release × Win32/x64.

```powershell
msbuild AESDumpster\AESDumpster.sln /p:Configuration=Release /p:Platform=x64
```

Linux (g++ 13+ / mingw-w64 for cross builds):

```bash
make           # Linux binary: ./aesdumpster
make debug     # -g -D_DEBUG
make windows   # cross-compile: aesdumpster.exe (mingw-w64, -municode -static)
make clean
```

Tests (Linux + wine for the Windows binary): `bash tests/run_tests.sh` — builds both targets and checks scanning against a synthetic fixture generated by `tests/gen_fixture.py`.

Debug builds use `debugmain()` in `AESDumpster/AESDumpster/AESDumpster/AESDumpster.cpp`, which scans a **hardcoded exe path** (`Z:\Exes\...`) — set your own path there or debug builds do nothing useful. Debug is Windows-only; on Linux `_DEBUG` falls through to `releasemain`. Release builds use `releasemain()` with drag-and-drop / command-line args (multiple exes per run are supported).

Known benign gcc warnings: `-Wmultichar` at the `(WORD)'\?\?'` literal in `Find()` (multichar value 0x3F3F on both compilers) and `-Wunused-result` on the unchecked `fread` in `CreateExeBuffer`.

## Architecture

Pipeline: **file buffer → pattern scan → dword extraction → entropy ranking → filtered print**.

- `Platform.h` (`AESDumpster/`) — compatibility header: on Windows it includes `<windows.h>`; elsewhere it shims `BYTE/PBYTE/WORD/PWORD`, `HANDLE`, `GetStdHandle`, and `SetConsoleTextAttribute` (ANSI escape codes), and picks `pathchar`/`pathstring` (`wchar_t`/`wstring` on Windows, `char`/`string` elsewhere) plus `pcout` (`wcout`/`cout`). All platform divergence lives here — new OS-specific code belongs in this pattern, not at call sites.
- `OtherTools` (`OtherTools/`) — CLI plumbing: intro/instructions printing and `CreateExeBuffer()`, which loads the entire exe into a raw `malloc`'d buffer (wide `stdio` calls on Windows, `fopen`/`ftello`/`fseeko` elsewhere). No PE parsing: the whole file is scanned linearly as bytes.
- `KeyDumpster` (`KeyTools/`) — the core scanner:
  - `Find()` scans the buffer for byte patterns with `?`/`??` wildcards (classic sig-scan, index-based).
  - `m_keyPatterns` and `m_keyDwordOffsets` are **parallel arrays** — pattern index `i` pairs with offsets index `i`. Each pattern matches 8 consecutive `C7` (mov dword ptr) instructions storing a 32-byte AES key; the offsets array holds the byte offset of each dword's immediate value relative to the match. Note offsets index 3 is in *reverse* order to match its pattern's reversed instruction order.
  - Candidates are ranked by Shannon entropy of the hex string (`CalcEntropy`). Keys with entropy < 3.3 are discarded; results are color-coded by entropy band; the max-entropy key(s) (`m_MostLikelyKey`) are the reported answer. `m_falsePositives` filters known constant blobs (SHA-256 constants, float arrays) that match the signatures.

Style quirks to preserve: objects are heap-allocated with raw `new` and torn down with explicit destructor calls (`key_dumpster->~KeyDumpster()`) and `malloc`/`free` — unconventional but consistent throughout; `_DEBUG` ifdefs gate verbose construction/destruction logging.
